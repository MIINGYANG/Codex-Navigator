# Agent 安装与自检指南

目标：在用户自己的机器上安装或更新 Codex Navigator，验证可运行，交付 `codex-nav` 终端版和 `codex-nav --web` 网页问题画布的使用方式。网页资源已内嵌，`codex-trail` 仅保留为兼容入口，不再提供旧网页阅读模式。只做安装和验证，不修改项目功能，不自行提交、发布或推送代码。

## 1. 确认源码与环境

- 使用用户提供的源码目录；若只提供仓库 URL，克隆到新的目录。不要覆盖已有工作目录，不猜测仓库地址，不安装未经确认的同名软件包。
- 阅读该版本 README；检查操作系统、CPU、`rustc --version`、`cargo --version` 与 C 链接器。当前仅 Linux x86_64 完成实机验收，其他平台先说明未验证，不承诺兼容。
- 工具链命令不存在或版本过旧时，先检查命令解析路径、已有 rustup 与 Cargo 安装目录，不直接跟随系统提示执行 apt/snap 安装。Bash/Zsh 默认 rustup 安装且 `~/.cargo/env` 存在时，可在当前进程 `source "$HOME/.cargo/env"` 后重新检查 `command -v cargo`、Cargo 与 Rust 版本；自定义目录按实际配置处理。只有确认现有工具链缺失或不满足要求后，才按用户授权安装或升级。
- 源码声明最低 Rust 1.88，推荐 stable。缺依赖时说明需要安装什么，按用户授权使用官方渠道；管理员权限、修改系统配置或未授权的安装覆盖必须先确认。不要为普通安装额外安装 Node、Docker 或浏览器自动化工具。
- 同时核对 Cargo 与 rustc 均为 1.88+，防止系统 Cargo 和 rustup Rust 混用。`lock file version 4 requires…` 是旧 Cargo 读取锁文件失败，不是锁文件损坏；不得删除/降级 Cargo.lock、添加 `-Znext-lockfile-bump` 或降低项目版本约束绕过。不要因此卸载系统 Rust，先修正工具链选择与 PATH。
- 检查是否已有 `codex-nav` / `codex-trail`，分别记录路径和版本。用户使用 README 的安装或更新指令时，已授权更新本项目安装，可使用 `--force`；不能覆盖来源不明的同名程序或其他软件。未授权更新时先确认，不要为了安装此项目升级或重装 Codex。2.0.0 起两个入口使用相同版本号。
- 不写入 `~/.codex`、`CODEX_HOME`、rollout 或 session_index，不输出或上传真实 Prompt、回复、认证配置及环境密钥。不要把用户主目录或 Codex 目录作为测试目录。

## 2. 测试、构建与安装

以下命令在源码目录执行；依次检查退出码，任何一步失败都先诊断，不把失败报告为完成。

```bash
cargo test --locked
cargo build --release --locked
cargo install --path . --locked
codex-nav --version
codex-nav doctor
```

用户要求更新且当前目录是本项目克隆时，先检查工作区，再执行 `git pull --ff-only` 和 `cargo install --path . --locked --force`；有本地改动或分叉先说明，不 reset 或覆盖。无需保留源码的安装/更新也可以在任意目录使用 `cargo install --git https://github.com/MIINGYANG/Codex-Navigator.git --locked --force`。更新前停止自己或用户明确指定的旧网页进程，更新后重新启动；不要把仍在运行的旧 binary 当作新版本。

- `cargo test` 已包含使用合成数据的解析、状态、增量读取及真实 HTTP 服务集成测试；不会向真实 Codex 会话写入测试记录。
- `cargo install` 将程序安装到 Cargo 的 bin 目录。找不到命令时检查实际安装输出与 PATH，安装后的绝对路径只用于诊断，不作为最终交付；Linux 默认主入口通常为 `~/.cargo/bin/codex-nav`。终端和网页均由此命令提供，`codex-trail` 只是兼容入口。
- 持久 PATH 是安装交付的一部分。用户使用 README 中的一句话指令时，已明确授权必要的当前用户 shell 配置修改，直接完成，无需重复询问；只有阅读指南不等于取得授权，用户未授权时仍先询问。管理员权限、覆盖其他软件及不相关系统修改需另行确认。
- 先识别用户实际使用的 shell、启动配置和安装目录，检查是否已有等价规则。修改前将配置备份到仓库外的用户私有目录，不输出或上传其中的令牌和其他内容；只最小追加必要行，不覆盖文件，不破坏 Conda/NVM/ROS 等配置，重复安装不重复追加。默认 rustup 且 env 文件存在时，Bash 的 ~/.bashrc 可添加 `[ -f "$HOME/.cargo/env" ] && source "$HOME/.cargo/env"`，放在交互式早退之后，并避免被后续 PATH 重置覆盖。Zsh 按实际 ZDOTDIR 下的 .zshrc 处理，其他 shell 使用其原生语法；自定义 Cargo 安装以实际 bin 为准。不要为此修改系统级配置或仅设置 alias。
- 配置后检查语法，并在源码之外从不含安装目录的初始 PATH 启动新交互式 shell，验证 `command -v codex-nav` 指向已安装程序，`codex-nav --version` 成功；适用时同时验证登录 shell。不要在验收命令里先 source Cargo 环境，否则无法证明持久配置生效。重复加载不应重复添加同一 PATH 项；已有终端应提示重新打开，而不是声称已自动更新。
- 切换到源码以外的目录，用新的对应 shell 验证主命令及版本，再在那里进行所选模式的启动验收。不要用只在 Agent 当前进程设置的 PATH 冒充新终端验证；无法验证用户终端时明确交由用户确认。不得用绑定源码目录的 alias、`cargo run` 或 `target/release` 路径代替安装。
- Web 资源编译进二进制，无需 `npm install`。若机器已有前端开发依赖，可补跑 `npm test`；未执行则在报告中注明，不声称完成前端测试。
- `doctor` 只用于诊断。没有历史会话属于正常空态；不能以它退出成功就断言发现了可读会话。实际查看需要用户已在本机使用过 Codex。

## 3. 按用户选择启动与验证

用户已指定终端版或网页版时直接按选择执行；未指定时交付两种启动命令，不默认只交付网页。先完成公共安装与测试，再按可用环境验证。

### 终端版

在独立交互式终端运行已安装的程序：

```bash
codex-nav
```

无需浏览器，不启动 HTTP 服务。若 Agent 具备交互式终端能力，确认主会话列表（无记录时为空态）；有会话时验证 `j/k` 选择、`Enter` 打开、`/` 搜索、`Tab` 切换焦点、`f` 定位最终回复、`s` 返回，最后退出并检查终端恢复正常。不要输出或上传会话内容。

按 `q` 退出（搜索时先按 `Esc`），或按 `Ctrl+C`。若 Agent 只有非交互命令执行能力，不要将后台运行或重定向输出当作终端验收；明确报告未验证交互，把启动命令交给用户在自己的终端执行。不需要为了使用终端版额外启动 Web 服务。

### 网页版：Question Trail 问题画布

使用已安装的程序启动，不要仅验证源码目录里的开发服务：

```bash
codex-nav --web --port 0 --no-open
```

此命令长期运行，`--port 0` 避免端口冲突。用 Agent 环境提供的后台进程机制保留它，并记录该进程的停止方式；若环境不能保留进程，验证后停止测试服务，让用户在自己的终端执行同一命令，明确说明并非已有后台服务。

从标准输出取得**实际完整 URL**，不要硬编码端口或构造令牌。可以使用现有 HTTP 工具验证：

1. 根页面与页面实际引用的 `/trail/assets/trail.js`、`/trail/assets/trail.css`、`/trail/theme-init.js` 均返回 200；旧 `/app.js` 等阅读页资源不再提供。
2. `/api/info` 不带令牌返回 403。
3. 从启动 URL 的 `#token=...` 取得本次令牌，以 `X-Codex-Nav-Token` 请求头访问 `/api/info`，应返回 200，版本与安装版本一致。
4. 同样带令牌请求 `/api/sessions`；若 `loading=true`，有界等待后重试，确认得到列表或明确空态。只报告数量和状态，不转发会话内容。

请求使用启动地址中的 `127.0.0.1` 与实际端口，不换成任意 Host。令牌只用于本次本机验证和给用户的启动地址，不写进仓库、公开日志或远程服务。

如具备浏览器操作能力，在本机打开完整启动 URL，确认进入问题画布并自动打开最近主会话。用户有会话时可验证切换会话、点击节点显示完整问题、前后跳转、Ctrl/Cmd+K 跨会话搜索、F 适配全图、拖拽/缩放和“原始对话”查看已有最终回复。顶栏“主题”应支持跟随系统、浅色、深色；手动设置后刷新保持。不要上传真实会话截图。

不要绑定公网地址或自动设置端口转发；如果 Agent 在远程机器上运行，说明 URL 属于那台机器的本机地址，不能让用户直接在另一台电脑访问。

`--codex-home PATH` 优先于 `CODEX_HOME`，否则读取 `~/.codex`。网页版只读扫描全部日期、项目的主会话；没有会话应显示空态和重新扫描。无法识别分支时单主线是正确退化，不依据问题内容补画分支。不要为了验收向真实 Codex 会话追加内容；实时更新测试应使用仓库提供的合成 fixture / 浏览器测试脚本。

Question Trail 展示的是已有用户问题的脉络，不是模型内部思维链；不需要 OpenAI API Key，不上传内容，不调用 AI。没有浏览器能力时明确仅完成 CLI/HTTP 验证，不把它称为完整画布或视觉验收。

## 4. 简短交付

向用户报告：安装路径与版本、所选模式、已通过/未执行的检查、是否找到会话、对应启动和退出方式，以及修改的 shell 配置、私有备份位置和新终端 PATH 验证结果。说明日常使用无需进入源码目录或手动 source；网页版另提供当前服务是否仍在运行及完整本机访问地址，终端版不需要 URL。不要只说“已部署”。

日后用户可任选一种方式启动：

```bash
codex-nav          # 终端版
codex-nav --web    # 网页版，自动打开浏览器
```

终端版用 `q` 退出（搜索时先按 `Esc`），或用 `Ctrl+C`；网页版前台服务用 `Ctrl+C` 停止。后台启动仅停止你创建并核实的那个进程，不用按名称批量杀进程。关闭浏览器标签页不会停止服务，停止 Navigator 不影响 Codex。

## Web 会话管理验收边界（3.0.0）

浏览和 doctor 保持只读；用户在网页主动改名/确认删除时才写入。改名需要 PATH 中的 Codex CLI，使用官方 app-server 元数据接口，会更新 CODEX_HOME 名称索引/数据库，也可能初始化 Codex 状态文件；不请求模型或恢复对话。删除当前仅支持 Linux `gio trash`，只移动选定 rollout，不永久删除或清理 Codex 数据库，恢复后需重启 Navigator。

安装指令不授权拿真实会话做改名/删除验收。管理测试必须隔离 CODEX_HOME、XDG_CONFIG_HOME、XDG_DATA_HOME，只创建合成会话；浏览器确认名称、cwd、取消无变化、成功和错误反馈，再核对 Codex 读回和回收站源字节。不要调用 `codex delete`、`thread/delete` 或永久删除命令。


## 画布收藏与事件验收（3.1.0）

新功能保留原问题画布，增加方向 / 密度切换、会话和问题收藏、代码提交与上下文压缩事件。收藏只写 `$XDG_DATA_HOME/codex-nav/favorites.json`（默认 `~/.local/share/codex-nav/favorites.json`），安装验收仍须隔离该目录，不能用真实会话试写收藏。可运行 `node scripts/features_qa.mjs`，使用合成数据验证重启 / 换端口持久化、桌面和窄屏布局及事件详情。排列偏好属于浏览器当前地址，换端口不保证保留。

提交和压缩只依据记录中的证据。工作路径不一定是 Git 根目录，旧压缩记录可能不含触发方式，缺少版本标签时显示哈希；不能为了补齐字段而运行历史命令或改写 Codex 源记录。


## 跨会话收藏问题验收（3.2.0）

侧栏“收藏”按全部 / 问题 / 会话展示，不要求先收藏父会话。使用隔离数据验证一个旧会话里的问题：父会话不收藏，问题收藏后能从侧栏查到并准确定位；搜索来源与路径、取消收藏、重启和源记录变更也应核对。执行 `node scripts/favorites_qa.mjs` 做桌面与窄屏验收；此脚本仅写合成数据和隔离 Navigator 收藏目录。
