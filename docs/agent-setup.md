# Agent 安装与自检指南

目标：在用户自己的机器上安装 Codex Navigator，验证可运行，交付终端版或网页版的使用方式。同一个二进制包含两种界面，无需分别安装。只做安装和验证，不修改项目功能，不自行提交、发布或推送代码。

## 1. 确认源码与环境

- 使用用户提供的源码目录；若只提供仓库 URL，克隆到新的目录。不要覆盖已有工作目录，不猜测仓库地址，不安装未经确认的同名软件包。
- 阅读该版本 README；检查操作系统、CPU、`rustc --version`、`cargo --version` 与 C 链接器。当前仅 Linux x86_64 完成实机验收，其他平台先说明未验证，不承诺兼容。
- 源码声明最低 Rust 1.88，推荐 stable。缺依赖时说明需要安装什么，按用户授权使用官方渠道；管理员权限、修改系统配置或覆盖已有安装必须先确认。不要为普通安装额外安装 Node、Docker 或浏览器自动化工具。
- 检查是否已有 `codex-nav`，记录路径和版本；不要直接加 `--force` 覆盖。不要为了安装此项目升级或重装 Codex。
- 不写入 `~/.codex`、`CODEX_HOME`、rollout 或 session_index，不输出或上传真实 Prompt、回复、认证配置及环境密钥。不要把用户主目录或 Codex 目录作为测试目录。

## 2. 测试、构建与安装

以下命令在源码目录执行；依次检查退出码，任何一步失败都先诊断，不把失败报告为完成。

```bash
cargo test --locked
cargo build --release --locked
cargo install --path . --locked
codex-nav --version
codex-nav doctor
```

- `cargo test` 已包含使用合成数据的解析、状态、增量读取及真实 HTTP 服务集成测试；不会向真实 Codex 会话写入测试记录。
- `cargo install` 将程序安装到 Cargo 的 bin 目录。找不到命令时检查实际安装输出与 PATH，可用安装后的绝对路径运行，不要擅自改写 shell 配置；Linux 默认路径通常为 `~/.cargo/bin/codex-nav`。
- 安装交付要求是用户在新终端、任意目录直接运行 `codex-nav`，不只是 Agent 通过绝对路径调用成功。检查用户实际使用的 shell 和安装目录；若需要持久化 PATH，先征求同意，再最小追加到相应配置，避免重复或覆盖现有内容。若用户不授权，说明当前仍需配置 PATH，提供临时命令，不声称快捷安装已全部完成。
- 切换到源码以外的目录，用新的对应 shell 验证命令解析路径与 `codex-nav --version`，再在那里进行所选模式的启动验收。不要用只在 Agent 当前进程设置的 PATH 冒充新终端验证；无法验证用户终端时明确交由用户确认。不得用绑定源码目录的 alias、`cargo run` 或 `target/release` 路径代替安装。
- Web 资源编译进二进制，无需 `npm install`。若机器已具备 Node 22.13+，可补跑 `node --test web/*.test.mjs`；未执行则在报告中注明，不声称完成前端测试。
- `doctor` 只用于诊断。没有历史会话属于正常空态；不能以它退出成功就断言发现了可读会话。实际查看需要用户已在本机使用过 Codex。

## 3. 按用户选择启动与验证

用户已指定终端版或网页版时直接按选择执行；未指定时简短询问使用哪一种，不默认只交付网页。先完成公共安装与测试，再按所选模式验收。

### 终端版

在独立交互式终端运行已安装的程序：

```bash
codex-nav
```

无需浏览器，不启动 HTTP 服务。若 Agent 具备交互式终端能力，确认主会话列表（无记录时为空态）；有会话时验证 `j/k` 选择、`Enter` 打开、`/` 搜索、`Tab` 切换焦点、`f` 定位最终回复、`s` 返回，最后退出并检查终端恢复正常。不要输出或上传会话内容。

按 `q` 退出（搜索时先按 `Esc`），或按 `Ctrl+C`。若 Agent 只有非交互命令执行能力，不要将后台运行或重定向输出当作终端验收；明确报告未验证交互，把启动命令交给用户在自己的终端执行。不需要为了使用终端版额外启动 Web 服务。

### 网页版

使用已安装的程序启动，不要仅验证源码目录里的开发服务：

```bash
codex-nav --web --port 0 --no-open
```

此命令长期运行，`--port 0` 避免端口冲突。用 Agent 环境提供的后台进程机制保留它，并记录该进程的停止方式；若环境不能保留进程，验证后停止测试服务，让用户在自己的终端执行同一命令，明确说明并非已有后台服务。

从标准输出取得**实际完整 URL**，不要硬编码端口或构造令牌。可以使用现有 HTTP 工具验证：

1. 根页面与 `/app.js`、`/app.css`、`/state.mjs` 均返回 200。
2. `/api/info` 不带令牌返回 403。
3. 从启动 URL 的 `#token=...` 取得本次令牌，以 `X-Codex-Nav-Token` 请求头访问 `/api/info`，应返回 200，版本与安装版本一致。
4. 同样带令牌请求 `/api/sessions`；若 `loading=true`，有界等待后重试，确认得到列表或明确空态。只报告数量和状态，不转发会话内容。

请求使用启动地址中的 `127.0.0.1` 与实际端口，不换成任意 Host。令牌只用于本次本机验证和给用户的启动地址，不写进仓库、公开日志或远程服务。

如具备浏览器操作能力，在本机打开完整启动 URL，确认主会话选择入口；用户有会话时可验证打开、搜索、最终回复定位与返回。没有浏览器能力就说明仅完成 HTTP 验证，不把它称为浏览器交互验收。不要上传会话截图。

不要绑定公网地址或自动设置端口转发；如果 Agent 在远程机器上运行，说明 URL 属于那台机器的本机地址，不能让用户直接在另一台电脑访问。

## 4. 简短交付

向用户报告：安装路径与版本、所选模式、已通过/未执行的检查、是否找到会话、对应启动和退出方式，以及新终端 PATH 是否验证通过。说明日常使用无需进入源码目录；网页版另提供当前服务是否仍在运行及完整本机访问地址，终端版不需要 URL。不要只说“已部署”。

日后用户可任选一种方式启动：

```bash
codex-nav                 # 终端版
codex-nav --web --port 0   # 网页版
```

终端版用 `q` 退出（搜索时先按 `Esc`），或用 `Ctrl+C`；网页版前台服务用 `Ctrl+C` 停止。后台启动仅停止你创建并核实的那个进程，不用按名称批量杀进程。关闭浏览器标签页不会停止服务，停止 Navigator 不影响 Codex。
